先看口径

“已登记”不等于“当前代理已启用”。价格表里有模型只表示 LiteLLM 能识别能力与默认成本；是否能从网关调用，要看 model_list、Admin UI 或数据库里是否创建了 deployment。价格为 0 表示尚未配置，不代表火山免费。

五种业务可以配置哪些计费

下面只列当前代码实际会读取的字段。价格表中的数值最终按美元字段落库，但本仓库对火山采用“人民币数字 1:1 记入美元数字”的特殊对账口径，并未做汇率换算。

文本对话 / Responses

费用 = 全部输入 token × 当前档输入价 + 全部输出 token × 当前档输出价 + 缓存命中 token × 当前档缓存价

按单次请求输入长度选一个档位，不是累进阶梯。当前边界是 32768 与 131072，判断条件为严格大于。

input_cost_per_token
output_cost_per_token
cache_read_input_token_cost
*_above_32768_tokens
*_above_131072_tokens
tiered_pricing

文生图 / 图生图 / 图片编辑

费用 = 输入图片数 × input_cost_per_image + 输出图片数 × 命中档输出图单价

输出图单价可按 usage.output_tokens 配任意多个阈值档；Seedream 5 Pro 当前以 16384 为普通/大图边界。

input_cost_per_image
output_cost_per_image
output_cost_per_image_above_{N}_tokens

视频生成

费用 = usage.completion_tokens × video_token_pricing[输入类型 + 分辨率]

先区分有无视频输入，再尝试分辨率后缀。当前 Seedance 用 token 计费；通用引擎还保留按视频秒数的兜底字段。

video_token_pricing.no_video_input
video_token_pricing.video_input
..._1080p / ..._4k
output_cost_per_video_per_second
output_cost_per_second

TTS 文本转语音

费用 = 输入字符数 × input_cost_per_character

当前登记 seed-tts-2.0，3 元/万字符，对应每字符 0.0003。支持 mp3、opus、wav、pcm。

input_cost_per_character
mode: audio_speech
endpoint: /v1/audio/speech

STT 语音转文字

费用 = 音频时长秒数 × input_cost_per_second

当前登记录音识别极速版 volc.bigasr.auc_turbo，4.5 元/小时，对应每秒 0.00125。时长取火山响应并由毫秒换算为秒。

input_cost_per_second
mode: audio_transcription
endpoint: /v1/audio/transcriptions

补充：多模态 Embedding

费用 = 文本 token × input_cost_per_token + 图片/视频帧 token × input_cost_per_image_token

两个 Vision Embedding 条目已配置文本与图像 token 价格；五个旧纯文本条目仍是零价占位。

input_cost_per_token
input_cost_per_image_token
mode: embedding
Chat 双配置

tiered_pricing 只用于请求前预算预留，不参与火山请求结束后的实际成本计算。实际落库依赖 input/output/cache_*_above_{N}_tokens。分档模型必须同时维护两套并保持一致。

两份 JSON 必须同步
源文件：model_prices_and_context_window.json。运行时本地备份：litellm/model_prices_and_context_window_backup.json。新增或改价时两边使用同一个 Key 和同一组价格。

      
自动映射条件
界面创建的 deployment 底层模型必须与价格表 Key 完全一致，例如 volcengine/doubao-seedream-5-0-pro-260628。刷新成本表后，调用返回的 usage 才会按这条 JSON 计算。

    

  


  

    

      
新增一个火山模型的标准流程
先判断是“部署接入”还是“代码库全局登记”，再按顺序执行。任何价格都要从官方页面或方舟模型信息读取，不凭旧配置猜。

    

    

      
确认 API 形态
确定属于 chat、image_generation、video_generation、audio_speech、audio_transcription 或 embedding，并确认实际 endpoint。

      
拿到准确模型 ID
价格表 Key 统一写成 volcengine/<model-id>；界面 deployment 的底层 model 必须与这个 Key 完全一致，客户端别名可以不同。

      
抄全官方价格档
记录单位、输入/输出类型、上下文边界、分辨率、是否含参考视频、普通图/大图等条件，并保存官方 URL。

      
换算为代码字段
元/百万 token 除以 1,000,000；元/千 token 除以 1,000；元/张直接写；元/小时除以 3,600；元/万字符除以 10,000。

      
配置 deployment
在 YAML 或 Admin UI 填 model、api_key、mode。特殊档位优先放 model_info，避免字段没有从 litellm_params 透传。

      
需要全局登记时同步两表
改 model_prices_and_context_window.json 与 litellm/model_prices_and_context_window_backup.json，写明 source 与币种口径。

      
补边界回归测试
分档价格至少测阈值减一、阈值、阈值加一；视频覆盖输入类型和分辨率；音频覆盖字符数或时长。

      
真实调用对账
调用本地代理，比较火山返回 usage、LiteLLM completion_cost 和日志中的 spend。最后执行相关测试及 make pre-commit。

这些是最容易出现“能调用但算错钱”的位置。

    

    

      

        
检查项当前行为新增模型时怎么做

        
          
人民币与美元字段火山人民币价格数字 1:1 写进 USD 成本字段保持现有口径并在 metadata.notes 写清楚；若要真正换汇，应先统一迁移策略

          
零价格条目旧 Chat 与纯文本 Embedding 有 0.0不要当作免费；上线前补官方价格或 deployment 覆盖

          
Chat 分档边界prompt_tokens > N 才进入 above_N火山边界是 32768/131072，不要缩写成 32k/128k

          
图片大图档依据响应 usage.output_tokens 选择最高越过档测 N、N+1，并确认火山响应确实返回 output_tokens

          
视频价格键先找输入类型 + 分辨率，找不到回落到输入类型基础键同时考虑 no_video_input 与 video_input，分辨率用小写后缀

          
Speech API BaseTTS/STT 默认走 openspeech.bytedance.com，不是 Ark Base使用 VOLCENGINE_SPEECH_API_KEY；不要把 Ark Base 强塞给语音接口

          
路由状态价格表不会自动创建 deployment去 Admin UI 或读取实际 model_list 验证；历史报告中的启用列表不代表当前环境
