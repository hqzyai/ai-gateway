ENDPOINTS

对外能力一览

POST/v1/images/generations

文生图；支持 SiliconFlow 扩展参数。上游请求发送到 /images/generations。

POST/v1/images/edits

上传 1–3 张图片；网关转为 data URI 后，仍以 JSON 调用上游图片生成端点。

POST/v1/videos

创建异步任务；上游走 /video/submit，立即返回 queued 与编码后的 video_id。

GET/v1/videos/{video_id}

查询任务；网关向 /video/status 发送 requestId 并标准化状态。

GET/v1/videos/{video_id}/content

任务完成后由网关读取结果 URL 并下载视频二进制；不支持 variant。

不支持list · delete · remix · content variant

当前 SiliconFlow 适配器会明确返回不支持，不应把这些能力暴露给调用方。

HOW TO CALL

按场景查看可复制示例

示例全部使用中文提示词
01

选择模型

模型名必须对应已配置的网关路由。

02

给出中文提示词

prompt 必填，负向提示词按需提供。

03

提交 JSON

size 会映射为 image_size。

04

读取 URL

仅支持 response_format=url。

curl · 文生图
curl -sS http://<gateway-host>:4000/v1/images/generations \
  -H "Authorization: Bearer $LITELLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Kwai-Kolors/Kolors",
    "prompt": "雨后的苏州园林，一只白猫坐在石桥上，电影光影",
    "negative_prompt": "模糊，低清晰度，文字水印",
    "size": "1024x1024",
    "n": 1,
    "seed": 42,
    "response_format": "url"
  }'
i

Kolors 专有映射

n 会映射为 batch_size；还可传 guidance_scale。Qwen-Image 使用 cfg。

curl · multipart 多图编辑
curl -sS http://<gateway-host>:4000/v1/images/edits \
  -H "Authorization: Bearer $LITELLM_API_KEY" \
  -F "model=Qwen/Qwen-Image-Edit-2509" \
  -F "prompt=保留第一张图的人物，把服装替换成第二张图的款式" \
  -F "image=@./person.png" \
  -F "image=@./clothes.png" \
  -F "size=1024x1024" \
  -F "response_format=url"
i

输入图数量

至少 1 张、最多 3 张。只有 Qwen/Qwen-Image-Edit-2509 支持多图；普通 Image-Edit 只允许一张。

01

提交任务

POST 后返回 queued。

02

保存 video_id

不要截断或自行解码。

03

轮询状态

queued / in_progress 继续等待。

04

下载成品

completed 后访问 content。

curl · 图生视频
curl -sS http://<gateway-host>:4000/v1/videos \
  -H "Authorization: Bearer $LITELLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Wan-AI/Wan2.2-I2V-A14B",
    "prompt": "镜头缓慢推进，海浪拍打礁石，云层随风移动",
    "input_reference": "https://example.com/first-frame.png",
    "size": "1280x720",
    "negative_prompt": "画面抖动，主体变形，闪烁",
    "seed": 42
  }'
!

当前没有时长参数

适配器不支持 seconds 或 duration。size 只接受 1280x720、720x1280、960x960。

bash · 查询并下载
VIDEO_ID='video_...'

curl -sS \
  -H "Authorization: Bearer $LITELLM_API_KEY" \
  "http://<gateway-host>:4000/v1/videos/$VIDEO_ID"

curl -sS \
  -H "Authorization: Bearer $LITELLM_API_KEY" \
  "http://<gateway-host>:4000/v1/videos/$VIDEO_ID/content" \
  --output result.mp4
queued

上游 InQueue，稍后轮询。

in_progress

上游 InProgress，继续等待。

completed

上游 Succeed，可下载。

failed

读取 error.message，停止轮询。

ERRORS & SECURITY

失败处理与安全边界

401 / Token is invalid

检查服务端 SiliconFlow Key 是否有效、模型路由是否引用了正确凭据。客户端 Virtual Key 与厂商 Key 不要混用。

400 / 参数校验失败

检查 response_format、seed、图片数量、视频 size，以及是否误传 duration、seconds 等不支持字段。

异步任务 failed

停止轮询并读取 error.message。只有 completed 才能请求 content。

密钥与日志

只在服务端保存 SILICONFLOW_API_KEY；示例、测试报告、日志和前端配置中都不得写入真实 Key。
